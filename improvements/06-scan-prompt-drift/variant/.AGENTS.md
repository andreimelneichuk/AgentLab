# Каталог: variant/

## Назначение
Вариант Basic-агента с методом SCAN против дрейфа системного промпта.

## Файлы

### scan.py
**Функции и типы:**
- `ScanLevel` — уровни FULL / MINI / ANCHOR / SKIP
- `ScanMarker` — маркер `@@SCAN_N` из промпта
- `parse_scan_markers(system_prompt)` — извлечение маркеров
- `resolve_scan_level(user_message, scenario_tags, config)` — выбор уровня
- `select_markers_for_level(markers, level)` — подмножество маркеров
- `build_scan_trigger(markers, user_message, level)` — триггер фазы SCAN
- `build_check_trigger(markers, scan_output, main_answer)` — триггер CHECK/MISSED
- `parse_scan_output(text)` / `parse_check_output(text)` — парсинг ответов

### agent_core.py
**Классы:**
- `AgentResources` — добавлено поле `scan_markers`
- `TurnResult` — поля `scan_output`, `scan_level`, `check_output`
- `BasicLoopSession`
  - `run_turn(..., scenario_tags, scan_level, enable_post_check)` — SCAN перед ходом
  - `_run_scan_phase()` — отдельный LLM-вызов без tools
  - `_run_check_phase()` — опциональная постпроверка
  - `_compose_visible_answer()` — сборка видимого ответа

### prompts/system_master.txt
Шесть маркеров `@@SCAN_1`…`@@SCAN_6` в секциях честность, инструменты, ошибки, HR/CRM, формат.

### config.yml
Секция `scan`: `enabled`, `default_level`, `post_check`.

## Зависимости
- `langchain_core`, `langchain_openai` — LLM
- `benchmark.compare` — прогон сценариев (из корня `experiments/`)
