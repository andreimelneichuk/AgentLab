# AI Agent Architecture & Experiments Benchmark

Репозиторий для исследования, разработки и тестирования архитектурных улучшений AI-агентов с поддержкой Tool Calling и MCP.

В репозитории представлены:
1. **Стандартный пайплайн (`original/`)** — эталонный базовый агентный цикл (LLM → Tool Executor → LLM) с интеграцией MCP.
2. **Исследовательские эксперименты (`improvements/`)** — 17 архитектурных подходов по улучшению базового пайплайна (валидация схем, детерминированная маршрутизация, сжатие контекста, графовый RAG, мультиагентная верификация и др.).
3. **Бенчмарк (`benchmark/`)** — инфраструктура сравнительного тестирования с мок-серверами MCP, оценкой качества (LLM-as-a-Judge) и анализом метрик.

## Структура

## Бенчмарк (из корня experiments/)

Каталог: **~500+ ходов**, **4 MCP-сервера**, **~25 инструментов** (core, hr, crm, sse).

```bash
source original/.venv/bin/activate
pip install -r requirements.txt

# перегенерация каталога (опционально)
PYTHONPATH=. python -m benchmark.generate_catalog --turns 500

# терминал 1 — mock MCP (все 4 mount на :19100)
python -m benchmark.mcp_mock_server

# терминал 2 — полный прогон
PYTHONPATH=. python -m benchmark.compare --variant original

# быстрый smoke (~5 сценариев с тегом smoke + critical)
PYTHONPATH=. python -m benchmark.compare --variant original --tags smoke

# эталонный стандартный пайплайн
PYTHONPATH=. python -m benchmark.compare --variant original

# экспериментальный вариант
PYTHONPATH=. python -m benchmark.compare --variant improvements/05-deterministic-routing/variant

# сравнительный анализ двух вариантов
PYTHONPATH=. python -m benchmark.compare --variant original --variant improvements/05-deterministic-routing/variant --metrics comparative
```

## Анализ экспериментов: реализация, результаты и выводы

В ходе исследований были проанализированы и протестированы **17 архитектурных подходов** к улучшению стандартного агентного цикла (Baseline Agent). Все эксперименты разбиты на 4 ключевых кластера:
1. **Tool Calling & Routing** — надежность вызова инструментов, предобработка аргументов и маршрутизация.
2. **Context & Memory Management** — управление длинным контекстом, сохранение фактов между сессиями и индексация.
3. **Knowledge & Graph-RAG** — графовые структуры знаний, валидация сущностей и устранение галлюцинаций в структурированных данных.
4. **Multi-Agent & Guardrails** — мультиагентная верификация, двухуровневые защитные фильтры (Tier-1/Tier-2) и инспекция безопасности.

### Детальный анализ ключевых решений

#### 1. Валидация и нормализация инструментов (`02-tool-validation-layer`)
* **Проблема v1:** Жесткая валидация строгих типов JSON Schema отвергала корректные вызовы с валидными числовыми строками (`"42"` вместо `42`) или формулами с пробелами (`" 2 + 2 "`), что приводило к обвалу SR до 14%.
* **Реализация v2:** Внедрен слой мягкого приведения типов (`_coerce_type`), нормализации параметров и очистки строковых выражений перед исполнением, а результаты пробрасываются в контекст.
* **Итог:** Рост Solve Rate до **75%** (+61 п.п.), Critical Solve Rate достиг **100%**.

#### 2. Детерминированная маршрутизация инструментов (`05-deterministic-routing`)
* **Проблема v1:** Роутер исключал системные инструменты (`graph_query`) из кандидатов и не распознавал контекстные реплики возврата к истории («в прошлом ответе», «там были»).
* **Реализация v2:** Интегрирован список обязательных `CORE_TOOLS`, расширен словарь синонимов доменов (HR, CRM) и внедрена динамическая подсказка `NO_TOOLS_HINT` для вопросов, требующих ответа из памяти.
* **Итог:** 100% покрытие Safety, экономия **25% токенов** за счет фильтрации нерелевантных схем, латентность снижена до 1.62s.

#### 3. Управление контекстом и индексы (`07-focus`, `09-context`, `15-memory`)
* **Контекстная инженерия (09):** Исправлено критическое нарушение контракта OpenAI/vLLM API (ранее разделение сообщений на блоки разрывало связку `assistant.tool_calls` и `tool_message`). При строгом сохранении adjacency получен CAS **82.0** и рекордная скорость 1.53s.
* **Knowledge Index (07):** Замена слепого сжатия истории на структурированный индекс знаний с сохранением защищенных токенов (`[PRESERVED_MARKERS]`) обеспечила наивысший Solve Rate среди всех вариантов — **80.0%**.
* **Долговременная память (15):** Устранен недетерминизм `hash()` между процессами Python за счет SHA-256 bucket-индексации. Факты сохраняются в SQLite с `UNIQUE(user_id, fact_key)` и мгновенно поднимаются при повторных сессиях.

#### 4. Безопасность и мультиагентная валидация (`12-multi-agent`, `13-buddy`, `14-graph-rag`)
* **Двухуровневый гейтинг (Tier-1 / Tier-2):** Безусловный вызов LLM-валидатора на каждом ходе приводил к огромным задержкам (>5.6s) и зацикливанию. Внедрение Tier-1 (детерминированная проверка запрещенных тулов, масок приманок и маркеров) отсекает 80% проверок без обращения к LLM. Задержка снижена до 1.78s при **100% Safety Pass** и **100% Critical SR**.
* **Защита графа (14):** Исключены ложные срабатывания гвардейла на непрофильных сценариях (CRM, общие знания). В графовых сценариях точность вызова инструментов достигла **100%**.

### Стратегические выводы и рекомендации к внедрению

1. **Базовый стек первого приоритета (Quick Wins):**
   * **Нормализация аргументов (02)** — обязательный компонент перед любым вызовом MCP. Предотвращает до 60% сбоев без дополнительных LLM-запросов.
   * **Контекстная инженерия с соблюдением adjacency (09)** — ускоряет обработку диалога и повышает CAS до 82.0.
   * **Tier-1 символические гвардейлы (12)** — моментальная проверка критических ограничений на стороне Python с нулевой латентностью.

2. **Стек второго приоритета (Production Scale):**
   * **Детерминированный роутинг (05)** — сокращает потребление токенов на четверть при сохранении качества ответов.
   * **Knowledge Indexing (07) + SQLite Memory (15)** — обеспечивает непрерывность диалога и точность работы с фактами при масштабировании сессий.
   * **Graph Guardrails (14)** — внедряется при подключении сложных корпоративных баз знаний и онтологий.
