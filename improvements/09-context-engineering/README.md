# 09 — Контекстная инженерия (Write / Select / Compress / Isolate)

**Tier:** 2  
**Источник:** GetMaxim (Kuldeep Paul), EmergentMind, JetBrains 2025  
**Проблема:** Переполнение контекста, потеря релевантного, квадратичный рост cost/latency

> **v2 (переработка):** v1 давал SR=13% (TA=23%, худшее среди всех вариантов) из-за
> трёх багов: (1) Isolate физически переставлял сообщения, ломая обязательный для
> OpenAI/vLLM API порядок `tool_call → tool_result`; (2) Select фильтровал сообщения
> по отдельности, оставляя осиротевшие ToolMessage без своего AIMessage;
> (3) `never_drop_patterns` защищал общие security-фразы, но не сами маркеры
> MCP-ответов (`EMP_ID=`, `violet-42`, ...), которые бенчмарк проверяет на recall —
> они маскировались уже на 3-м ходу. Все три исправлены в v2, см. IMPLEMENTATION.md.

## Четыре стратегии

### Write — запись за пределами окна

**Скретчпад:** агент ведёт рабочие заметки во внешнем хранилище.

```
В контексте: ссылка "см. scratch:policy_lookup_042"
На диске/Redis: полный результат get_policy_fact
```

Подходит для больших JSON-ответов MCP.

### Select — умная фильтрация

Динамический выбор релевантных фрагментов истории:

- Простой уровень: keyword matching по текущему запросу
- Продвинутый: semantic similarity (как в 08, но для history chunks)

### Compress — компрессия

Иерархическая суммаризация:

- Недавние ходы — дословно
- Старые — краткое summary

**JetBrains 2025 (250-ходовые траектории):** masking и LLM-суммаризация снизили cost на 50%+; **masking часто лучше по solve rate**, чем LLM-summary.

### Isolate — изоляция

Разные типы контекста в разных «слотах»:

- Системные правила (не смешивать с tool XML)
- Факты сессии vs диалог vs RAG-документы
- Multi-agent: каждый агент — свой срез

## Context Rot (EmergentMind)

Деградация начинается **задолго до лимита токенов**. Больше контекста = больше шума, не больше памяти.

Эффект «lost in the middle»: информация в середине контекста теряется (до −30% точности).

## Что менять в Basic

| Стратегия | Файл / модуль |
|-----------|---------------|
| Write | `scratch_store.py` + tool `save_scratch` / `load_scratch` |
| Select | Фильтр history перед `invoke` |
| Compress | Политика: last-N verbatim + summary старого |
| Isolate | Отдельные message blocks: rules / tools / chat |

### Приоритет для бенчмарка

1. **Isolate** — system prompt и tool results не перемешивать в одном blob
2. **Compress** — masking старых tool XML (дешевле LLM-summary)
3. **Write** — большие ответы CRM lookup
4. **Select** — релевантные прошлые ходы при multi-turn

## Критерии успеха

- Стабильный pass rate на `catalog` при −30% median tokens
- `s04_003` (2 хода): факт из хода 1 доступен на ходе 2
- Нет регрессии на `s10_adversarial` (не выкидывать security rules)

## Антипаттерны (из документа)

- Наивное удаление **старых** сообщений — выбрасывает ещё нужное
- Только LLM-суммаризация — lossy, хуже masking по JetBrains
- Ждать автокомпрессии от провайдера — нужна **проактивная** политика
