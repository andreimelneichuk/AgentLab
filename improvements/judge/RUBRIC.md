# Рубрика судьи оконченности доработок

Судья оценивает **насколько доработка завершена относительно спеки**, а не только наличие файлов.

## Шкала итога (0–100)

| Балл | Вердикт | Критерий |
|------|---------|----------|
| 90–100 | Production-ready | Спека закрыта, тесты зелёные, интеграция в agent loop, бенчмарк ≥ baseline или целевая метрика достигнута |
| 75–89 | Beta | Ядро реализовано, 1–2 пункта чеклиста открыты, бенчмарк близок к baseline |
| 50–74 | Alpha | POC работает, существенные пробелы (нет E2E, нет интеграции, чеклист <70%) |
| 25–49 | Draft | Заготовки + unit-тесты, основной flow не подключён |
| 0–24 | Stub | Только документация или копия original без изменений |

## Пять измерений (по 0–20, сумма = итог)

### 1. Покрытие спеки (0–20)
- Все обязательные пункты README/чеклиста
- Архитектура из спеки реализована, не «на бумаге»
- Штраф −5 за каждый критичный незакрытый пункт

### 2. Качество кода (0–20)
- Модульность, читаемость, соответствие стилю `original/`
- Нет мёртвого кода / неиспользуемых флагов
- Ошибки обрабатываются осмысленно

### 3. Тесты (0–20)
- Unit-тесты на ключевое поведение (не только happy path)
- `pytest tests/` в variant проходит
- Штраф −10 если тесты не запускались или падают

### 4. Интеграция в агент (0–20)
- Изменения реально в `run_turn` / tool loop / prompt
- Конфиг `config.yml` согласован
- Бенчмарк `compare.py` может прогнать variant (путь, backends)

### 5. Эффективность / production (0–20)
- SR vs baseline 26% (`improvement_reports/SUMMARY.md`)
- Целевые метрики доработки (r_nta, r_dt, TSA, AH, latency)
- Документация: `IMPLEMENTATION.md` достаточна для онбординга

**Штрафы к измерению 5:**
- SR на 10+ п.п. ниже baseline без объяснённой trade-off: −10
- Latency >3× baseline без документированной причины: −5
- Открытый `QUESTIONS.md` без `DECISIONS.md`: −3

## Артефакты судьи

Каждый судья пишет:

1. **`improvement_reports/judge/judge_NN.md`** — полный отчёт (таблица измерений, gaps, рекомендации)
2. **`improvements/NN-*/JUDGE.md`** — краткая сводка (≤30 строк)

## Формат краткого JUDGE.md

```markdown
# Judge Report — NN-name

**Оценка оконченности:** XX/100 — **Вердикт**

| Измерение | Балл |
|-----------|-----:|
| Спека | /20 |
| Код | /20 |
| Тесты | /20 |
| Интеграция | /20 |
| Production | /20 |

**Бенчмарк:** SR=…% (baseline 26%)

## Главные пробелы
- …

## Рекомендации (топ-3)
1. …
```
