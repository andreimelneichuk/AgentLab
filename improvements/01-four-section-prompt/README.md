# 01 — 4-секционный системный промпт

**Tier:** 1 (минимально необходимый)  
**Источник:** RoboRhythms (Nathan Cole), Indie Hackers / Claude Code  
**Проблема:** Выдуманные инструменты, неверные параметры, перекрёстная путаница похожих tools

## Суть проблемы

Работающий агент — это не «модель + tools», а модель с **структурой принятия решений**. Размытая роль и неопределённые схемы заставляют LLM заполнять пробелы: выбирать не тот инструмент, передавать неверные параметры, молча «восстанавливаться» после ошибок.

Документ утверждает: такой промпт перекрывает **~95% галлюцинаций параметров** (при наличии слоя валидации — см. 02).

## Структура промпта (строгий порядок)

### Секция 1: Роль и область действия

Один абзац: что агент **делает** и что **НЕ делает**.

```
Ты агент Baseline Agent, который помогает сотрудникам с HR/CRM/справочниками.
Ты НЕ отправляешь письма, НЕ меняешь данные без явного запроса.
Ты НЕ вызываешь инструменты вне списка Секции 2.
```

Негативная область — главный недостающий элемент в большинстве промптов.

### Секция 2: Инструменты со строгими схемами

Для **каждого** инструмента — 5 элементов в фиксированном порядке:

1. Имя
2. Назначение
3. Схема входа (типы, форматы, обязательные поля)
4. Схема выхода (что ожидать)
5. **«НЕ использовать когда»** — отсекает путаницу с похожими tools

Пример для бенчмарка:

```
get_policy_fact — официальный факт политики (violet-42).
НЕ использовать: decoy_policy_fact (устаревшая приманка).
```

### Секция 3: Правила принятия решений

Явные if/then, не «используй суждение»:

- Порядок вызовов (сначала lookup, потом детали)
- **STOP при ошибке** — залогировать и остановиться, не подставлять заглушки
- Запрет продолжать с деградированными данными

Критично для CRM-сценариев: ~⅓ неверных записей — из молчаливого recovery.

### Секция 4: Формат вывода

Структурированный JSON или фиксированные маркеры (`[POLICY_OK]`), чтобы downstream-код не парсил свободный текст.

## Что менять в Baseline Agent

| Файл | Действие |
|------|----------|
| `original/prompts/system_master.txt` | Разбить на 4 секции по шаблону выше |
| `agent_core.py` | Убедиться, что весь system prompt загружается целиком |
| Описания MCP tools | Синхронизировать с Секцией 2 (имена, «не использовать когда») |

## Критерии успеха (бенчмарк)

- Снижение `tool_args`, `r_dt`, `r_nta` на smoke и `s04_policy_nta`
- Рост `critical_scenarios_passed`
- Сценарии `s09_instruction` — агент следует явным правилам из Секции 3

## Ограничения

- Промпт — **рекомендации**, не ограничения. Без 02 (валидация) ~1 из 30 вызовов всё равно с ошибкой параметров.
- В длинных сессиях секции деградируют (дрейф) — нужен 06 (SCAN) или 13 (Buddy).

## Зависимости

- Нет внешних библиотек
- Рекомендуется в паре с: **02**, **04**
